The Meshless Protocol, written down.

An application-layer protocol for discovering, authorizing, and invoking resources across independently administered nodes. Draft 00 is a complete reading draft, not a stable standard.

How to read it

Sections 1–4 establish scope, status, and the trust model. Sections 5–12 are the wire: profile, identity, descriptors, discovery, grants, proofs, endpoints, and receipts. Sections 13–16 cover failure behavior, revocation, adapters, and security. Sections 17–19 are process and references. Appendix C records the corrections made before publication — read it if you have seen an earlier draft, because four of them change the wire format.

The keywords MUST, MUST NOT, SHOULD, and MAY carry the meanings defined in BCP 14. Where the draft is provisional — the well-known discovery path, the transport adapter API, the doxx.net pilot — it says so explicitly, and this site repeats it rather than smoothing it over.
