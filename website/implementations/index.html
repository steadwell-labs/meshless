Implementations

Nothing here is finished.

MLP/1 is a working draft. No implementation yet demonstrates baseline conformance, and this page will say so until one does. There is no certification program, no compatibility mark, and no vendor to call.

Current state

One implementation, self-tested.

The repository contains a dependency-free TypeScript implementation of the wire format, a provider, a consumer, and a command line tool, with a conformance suite covering the twenty cases in §17.1 and published fixtures in test-vectors/.

It has been tested by its own authors and nobody else. That is evidence the code agrees with itself, not that it interoperates. No independent implementation has been run against the vectors, and the protocol has had no security review.

“Conformance” here means an independent party reproduces the results in §17 of the draft against the published fixtures. One implementation passing its own suite does not meet that bar, so this table stays at “self-tested” until someone else does.

What “in progress” means

The reference implementation covers the MLP/1-HTTP profile: descriptor and grant verification, single-use proofs, atomic quotas, receipts, revocation, and a TLS 1.3 server with no plaintext mode. It is a single-process provider backed by a JSON snapshot, and it refuses to claim more than that.

What it does not do: no independent implementation has been tested against it; no streaming, no multi-replica provider, no in-band key rotation, no doxx.net adapter. The gaps are listed in §16 and tracked in the repository.

No performance figures, coverage numbers, or compatibility claims are published on this page. A loopback benchmark of a single-process gateway would measure a socket, not a protocol.

Submit an implementation

If you are building an independent consumer or provider, the draft is meant to be implemented against, and disagreement is useful. Open an issue or a pull request in steadwell-labs/meshless describing the language, the profile you targeted, the tests you ran, and how someone else can reproduce them.

Entries are listed here only when there is something reproducible to point at. A user interface over a mocked provider is not an implementation; neither is a claim that has not been tested against a second party. The long-term goal is independent interoperability, which the draft makes a precondition for any stable 1.0 designation — not a milestone this project can declare on its own.
